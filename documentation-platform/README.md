# Snow Seasons Tech — Documentation Platform

Docs-as-code generator for SaaS product documentation. One product definition in `products/` produces Markdown, Word, and (with Pandoc) PDF documents from approved templates.

**Status: Phase 1 (documentation engine) — pilot product `cdot-stations`.**

## Layout

```
products/<id>/product.yaml   Product registry entry (source of truth)
templates/*.md.j2            Jinja2 templates; strict, so missing fields fail the build
generator/                   Validation, rendering, DOCX/PDF export, CLI
tests/                       pytest suite
.github/workflows/           Validate and build on every change
build/                       Generated output (not committed)
```

## Usage

```bash
uv sync
uv run pytest
uv run python -m generator --all --validate-only
uv run python -m generator --product cdot-stations --format all
```

Output goes to `build/<product>/`: `product-overview.md|.docx|.pdf`, `getting-started.*`, `pricing-sheet.*`, and `manifest.json` (source hashes, warnings, skipped files).

PDF needs `pandoc` and a LaTeX engine on PATH. Without pandoc the PDFs are listed under `skipped` in the manifest and the build still succeeds.

## Rules the generator enforces

- Documents only contain features listed in `product.yaml`. Templates never add features.
- Prices are not stored here. `billing.pricing_source` must be `stripe`, and plans reference `stripe_price_id`.
- Unsupported document types, bad statuses, non-semver versions, and missing access or support fields fail the build.
- Unfilled template markers (`TODO`, `TBD`, leftover Jinja syntax) fail the build.
- Warnings are reported but do not block: unconfirmed features, unlinked Stripe prices, empty limitations on pre-release products.

## Before a pilot document is published

1. Product owner confirms the feature list and sets `features_confirmed: true`.
2. Stripe price IDs are filled in for each plan.
3. Known limitations are listed for pre-release status.
4. Legal and contract documents are not generated by this tool. They use counsel-approved templates.

## Repository note

This folder sits inside the `snowseasonstech-website` repo for now. The design calls for a dedicated `documentation-platform` repository. If you move it, the workflow in `.github/workflows/` only runs from the repository root, so it will not run while the folder stays nested here.
